# Rivet Audit — отчёт этапа 0.3.0a0

Дата проверки: 2026-10-07. Проверка выполнена в существующем проекте, без публикации на GitHub.

## VERSION

`0.3.0a0`. Собран wheel и установлен в новое виртуальное окружение без сетевых зависимостей.

## READINESS

**ALPHA.** Четыре внешних сканера действительно работают, но критерии BETA не выполнены: SCA и SBOM охватывают ограниченные источники, межфункциональный анализ не переходит между файлами, auth/authz остаётся эвристическим, а динамический режим ограничен HEAD.

## IMPLEMENTED THIS STAGE

- Устранено дублирование находок Semgrep/Bandit и встроенного движка по CWE и местоположению. Внешний `HIGH` без подтверждения остаётся `MEDIUM`.
- Для адаптеров добавлены проверка кода завершения и структуры JSON, безопасное сообщение об ошибке, статусы `COMPLETED`, `DISABLED`, `NOT_INSTALLED`, `FAILED`, `TIMEOUT`, определение версии в `doctor`. Gitleaks пропускает историю вне Git-репозитория; OSV различает отсутствие источников и сбой.
- OSV-Scanner v2 вызывается через `scan source`; его результаты содержат нормализованные данные о пакете, версии, advisory, CVE/GHSA, диапазоне и доступной исправленной версии. Неизвестная достижимость обозначается `UNKNOWN`.
- `rivet sbom` создаёт локальный CycloneDX 1.6 JSON из закреплённых Python `requirements*.txt` и npm `package-lock.json` v2/v3. Для npm учитываются прямые и транзитивные связи, dev-флаг и integrity-хэши при наличии.
- Python AST отслеживает ограниченные цепочки в одном файле через аргументы и простые обёртки. Введены пределы глубины, количества посещённых узлов и времени. Отпечаток находки с доступным исходным кодом сохраняется при сдвиге строк и изменении пробелов.
- Уточнён вывод о маршрутах: ссылка на `owner_id` сама по себе больше не считается проверкой прав; кандидаты обозначены `POSSIBLE_BOLA`, матрица помечена `INFERRED`.
- Динамический HEAD-проверяющий блокирует metadata/link-local/служебные адреса, не следует перенаправлениям, проверяет DNS и соединяется с закреплённым проверенным IP. Для TLS сохраняются hostname и SNI.
- Добавлены узкие статические проверки MCP-конфигурации: shell-команда, широкий корень filesystem-сервера и незашифрованный удалённый HTTP. Результаты требуют ручной проверки.
- Добавлены тесты сквозной редактуры тестового секрета во всех отчётах и экранирования HTML.

## TESTS

**87 тестов пройдены** с установленными бинарниками и разрешённой локальной сетью: 4 проверки реальных внешних сканеров, 11 self-security проверок, 1 настоящий loopback HEAD и 71 прочий unit/regression тест. В ограниченной песочнице сетевые интеграции и bind loopback пропускаются при отсутствии разрешений. Изолированный wheel установлен и выполнил `--help`, `doctor`, secure fixture, interprocedural/MCP/Kubernetes fixtures, SBOM и онлайн OSV.

Синтетический замер встроенного сканирования: 1000 файлов — 0,425 с; 5000 — 1,306 с; 10000 — 2,08 с на данной машине. Память и медленные CI-машины этим замером не характеризуются.

## SCA

Реально проверен PyPI через OSV на `requirements.txt`. Нормализация OSV пригодна для других поддержанных самим OSV источников, но npm/cargo/go advisory через Rivet в этом этапе отдельно не валидировались. `pip-audit`, `npm audit`, `cargo audit`, `govulncheck` пока не подключены. Directness, environment и reachability без доказательств остаются `UNKNOWN`.

## SBOM

Проверены Python pinned requirements и npm package-lock v2/v3. CycloneDX содержит компоненты, версии, purl, отношения зависимостей и npm integrity-хэши, когда они есть. Не закреплённые Python зависимости и другие lockfile-форматы не включаются; это не полная инвентаризация проекта.

## DATA FLOW

Поддержаны локальные aliases, передача аргументов между функциями в одном файле и простая цепочка route → service → repository. Проверенная фикстура фиксирует источник FastAPI-параметра и SQL sink. Также сохраняются ранее существовавшие источники Flask/Django request-полей и локальные sink-правила. Импорты, динамическая диспетчеризация, сложные возвраты, точная модель санитайзеров и межфайловые цепочки пока не подтверждены.

## AUTH/AUTHZ

Есть AST-проверки отдельных опасных auth-паттернов и эвристическая матрица endpoint → authentication → authorization → resource/action. FastAPI `Depends(get_current_user)` и некоторые декораторы распознаются как признаки, а не как доказательство. BOLA без динамического теста — `POSSIBLE_BOLA`, `MEDIUM`, `NEEDS_MANUAL_REVIEW`. Полной проверенной матрицы ROLE × ENDPOINT × METHOD нет.

## DYNAMIC TESTING

По умолчанию выключен. Требует `--test-environment`, допускает loopback или явно разрешённый host, отправляет один HEAD с таймаутом 5 с, без redirect и без тела запроса. DNS-ответ проверяется, соединение закреплено на выбранном IP; metadata и link-local блокируются. Настоящий loopback HEAD прошёл. OPTIONS/GET и отрицательные API-тесты ещё не включены.

## AI/MCP

Существующие AST-проверки AI-output sinks и небезопасной загрузки дополнены статическим разбором известных JSON-файлов MCP. Не анализируются реальные разрешения инструментов, поведение удалённого сервера или prompt injection во время выполнения.

## VIBE PROFILE

Сохранён существующий профиль с понятными объяснениями для нескольких типичных настроек. В этом этапе общее качество повышено за счёт deduplication, SCA и точности route/MCP сигналов; полного списка сценариев `vibe` из плана нет.

## FALSE POSITIVE CHECK

Установленный wheel на `secure-reference` дал **0 находок**. Новые негативные тесты проверяют чистую MCP-конфигурацию, параметризованный/валидированный путь, чистый OSV manifest и отсутствие ложного вывода об authorization по одному полю `owner_id`.

## DOGFOODING

Установленный Rivet 0.3.0a0 просканировал собственный проект с Semgrep/Bandit и офлайн-режимом: **0 HIGH, 20 MEDIUM, 23 LOW**. Большинство MEDIUM относятся к намеренно уязвимым фикстурам и поддельным тестовым секретам. В собственном `src` осталось 4 LOW Bandit-предупреждения о преднамеренном использовании `subprocess` для адаптеров; Semgrep дал 0. Gitleaks `--no-git` для `src` дал 0, а в полном дереве отметил поддельные fixture-ключи. OSV для самого проекта сообщил `SKIPPED`: поддержанного dependency source нет, runtime dependencies в `pyproject.toml` пусты. Git history проекта отсутствует, поэтому аудит истории собственного проекта не проводился.

## KNOWN LIMITATIONS

- Нет полной цепочки SCA для Python/Node/Go/Rust, доказательства достижимости и проверенной полноты advisory.
- SBOM пока не разбирает `pyproject.toml`, Poetry, uv, pnpm, yarn, Go и Cargo; Python graph не содержит транзитивные связи.
- Межфункциональный поток ограничен одним файлом и простыми локальными вызовами; нет точной модели всех санитайзеров.
- Auth/authz и BOLA остаются inference; нет верифицированной role matrix.
- Dynamic mode ограничен HEAD; отсутствуют OpenAPI negative tests и строгая модель всех stateful endpoints.
- Kubernetes, Terraform, mobile, cloud, Electron/Tauri, GraphQL, WebSocket и business logic покрыты частично или не покрыты.
- MCP анализирует только определённые JSON-конфигурации; не доказывает вредоносность сервера.
- Нет suppression с причинами и сроком, безопасных autofix с diff-preview, property-based fuzzing и внешнего SARIF validator в этом этапе.
- Development dependencies и внешние scanner binaries не закреплены lockfile проекта; проверенные версии задокументированы.
- Выполнены временные 1000/5000/10000-файловые замеры времени, но не профилирование памяти.

## VERIFIED FEATURES

Проверены реальными тестами: сборка и чистая установка wheel; четыре формата отчёта; secure fixture; указанные внешние бинарники; OSV PyPI fixture; ограниченный CycloneDX; Python flow fixture в одном файле; локальный HEAD HTTP; redaction тестового секрета во всех форматах; HTML escaping; baseline при сдвиге строк; статические Kubernetes и MCP fixtures.

## NEXT STAGE

Для BETA нужны более широкая проверенная SCA/SBOM по основным экосистемам, межфайловый flow, улучшенная auth/role-модель, расширенные безопасные API-тесты, полный invariant редактуры для всех scanner error paths, проверка SARIF внешним валидатором и фиксированные development dependencies. RC/1.0 потребует отдельного анализа эксплуатационной безопасности, ложных срабатываний и совместимости на разных ОС.
